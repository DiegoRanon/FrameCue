# Architecture

Companion to `docs/MVP_SPEC.md` (what and why) and `docs/DECISIONS.md` (what was chosen and why).
This file describes how the pieces fit together. It is updated as milestones land.

## Shape

One Expo/React Native app with two roles, LiveKit Cloud for live media, Supabase for everything that is not
media, and a local native module for the replay buffer. The backend never receives a media artifact - that
is the structural guarantee behind FR-15, NFR-09, and AC-13, not a policy.

```
Coach device                          Student device
+------------------------------+      +------------------------------+
| Expo app (coach role)        |      | Expo app (student role)      |
|  live view / replay controls |      |  live view / replay view     |
|                              |      |                              |
| modules/replay-buffer        |      |                              |
|  VideoSink -> encoder        |      |                              |
|  ring buffer (~30-35 s)      |      |                              |
|  prepare() -> temp MP4       |      |  received temp MP4           |
+------------------------------+      +------------------------------+
        |          |                          |          |
        |          +----- clip transfer ------+          |
        |          +----- control messages ---+          |
        |                                                |
        +----------------- live A/V ---------------------+
                             |
                      LiveKit Cloud (SFU, TURN, signaling)

  Supabase: coach auth, sessions, invitations, non-media events.  No storage bucket.
```

## Layout

| Path                    | Holds                                                           | Lands in |
| ----------------------- | --------------------------------------------------------------- | -------- |
| `src/app`               | Expo Router screens. File-based routing also serves deep links. | M0+      |
| `src/config`            | Environment resolution (`app.config.ts` extra -> typed access). | M0       |
| `src/call`              | LiveKit room connection, track subscription, connection state.  | M1       |
| `src/replay`            | Pending-replay state machine and the native module bridge.      | M2, M3   |
| `src/control`           | Data-channel message schema and transport. Coach is the source. | M4       |
| `modules/replay-buffer` | Local Expo module. Kotlin now, Swift at M8, one TS interface.   | M2, M8   |
| `scripts`               | Build helpers, e.g. pinning the Gradle JDK after prebuild.      | M0       |

`android/` and `ios/` are generated by `expo prebuild` and git-ignored. The only native source under
version control lives in `modules/`.

## Replay flow

1. The coach subscribes to the student's video track through LiveKit.
2. `modules/replay-buffer` attaches a sink to that track and encodes frames on arrival, retaining the newest
   30-35 seconds of **encoded** samples. Encoding on ingest is what keeps the buffer at single-digit
   megabytes instead of gigabytes (NFR-05).
3. `prepare(15 | 30)` muxes the trailing interval into a temporary MP4 and returns its path and true
   duration. The live call is untouched, and the student sees nothing (FR-10).
4. The clip is pushed to the student in the background while the replay sits pending (D-001).
5. `Show Replay` sends a control message; both sides play their local copy, coach commands authoritative,
   drift corrected to under ~500 ms (NFR-02). Replay audio is muted; microphones are untouched (FR-12).
6. `Return to Live` tears down review on both sides without touching the LiveKit connection (NFR-03).
7. Discard, replace, return-to-live, session end, and app start all delete the clip and reset the buffer
   (FR-16, AC-12).

## Constraints that shape the code

- **Nothing survives the session.** No media path may lead to a bucket, an account, a share sheet, or a
  gallery. Clips live in the cache directory and are deleted explicitly.
- **Preparing must never disturb the live call.** Encoding runs off the render path; a failure in the replay
  pipeline is reported and swallowed, never propagated into the call (NFR-04).
- **The coach is authoritative.** The student's UI renders received state and sends nothing.
- **Bounded memory.** The ring buffer has a hard cap; ten prepare/show cycles must not grow it (AC-11).
